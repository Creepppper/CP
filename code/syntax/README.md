# MINI 语法分析实验

## 当前进度

实验二的五个阶段已完成：文法整理、语法分析、符号表构造、错误恢复和文件输出、测试与结果整理。

## 环境

需要 CMake 3.16 或更高版本和支持 C++17 的编译器。在本目录运行：

```sh
cmake -S . -B build
cmake --build build
```

第二条命令生成 `build/mini_parser`。例如先在 `../lexical/` 目录运行词法分析器生成 `output/sample1.dyd`，再回到本目录运行：

```sh
./build/mini_parser ../lexical/output/sample1.dyd
./build/mini_parser ../lexical/output/sample2.dyd
```

第一个样例输出 `Syntax analysis succeeded.` 及变量表、过程表；第二个样例会报告多处错误。两个样例都会在本目录的 `output/` 中生成 `.var`、`.pro` 和 `.err` 文件。

`build/` 和 `output/` 是生成目录，不纳入版本管理。老师给出的源程序复用 `../lexical/tests/` 中的样例，不再复制一份。

## 输入与输出约定

输入为实验一生成的 `.dyd` 文件，每行是“单词符号 空格 种别码”。种别码沿用实验一的对照表，不再由语法分析器重新进行词法分类。

- 从第 1 行开始记录源程序行号。`EOLN 24` 表示源程序的一行结束：读取时更新行号，语法匹配时跳过。
- `EOF 25` 表示单词序列结束。程序结构匹配完成后必须到达 `EOF`；若遇到未完成的结构，在最后一个源程序行报错，空文件按第 1 行处理。
- `.dyd` 中单词记录格式错误、种别码无效、固定单词与种别码不匹配、末行缺少 `EOLN`、缺失 `EOF` 或 `EOF` 后还有记录时，作为输入文件错误报告，不能当成正常语法分析结果。输入错误中的行号是 `.dyd` 的记录行号；语法错误中的行号是源程序的行号。
- 先检查实验一的 `.err`。语法分析器不会自动读取它；若有词法错误，不应把跳过非法字符后的 `.dyd` 当成完整正确的源程序。

程序以 `.dyd` 路径作为命令行参数，在当前工作目录的 `output/` 中生成同名 `.var`、`.pro`、`.err`。例如从 `syntax/` 运行时，输入 `../lexical/output/sample1.dyd`，生成 `output/sample1.var`、`output/sample1.pro` 和 `output/sample1.err`。同名结果会覆盖，语法错误文件与 `lexical/output/` 中的词法错误文件分开。如果输出会覆盖输入文件或其同目录、同名的词法错误文件，程序会拒绝写入，此时应从 `syntax/` 目录运行。

语法错误按 `***LINE:行号 错误性质` 记录；名称过长等符号表错误也写入 `.err`，并注明错误类别。没有错误时 `.err` 为空，有错误时程序返回非零状态。程序会尝试在分号、`else`、`end` 等位置恢复并继续分析；恢复可能引出后续错误，也不保证发现所有错误。出现错误时仍会输出已识别声明的表项，但表可能不完整。

文件不存在或 `.dyd` 格式损坏属于输入错误，程序在终端报告并返回非零状态，不更新结果文件。如果此前已有同名结果，旧文件仍会保留，不应误认为本次输出。

## 改写后的文法

下面使用扩展 BNF：`{ ... }` 表示重复零次或多次，`[ ... ]` 表示可有可无。`标识符`和`整数`分别是词法分析的种别 10 和 11。关键字及符号均以单词为单位匹配。

```text
程序         → 分程序 EOF
分程序       → begin 说明语句 ; 说明后的内容 end
说明后的内容 → 说明语句 ; 说明后的内容 | 执行语句表
说明语句     → integer 说明后缀
说明后缀     → 标识符 | function 标识符 ( 标识符 ) ; 分程序

执行语句表   → 执行语句 { ; 执行语句 }
执行语句     → read ( 标识符 )
             | write ( 标识符 )
             | 标识符 := 算术表达式
             | if 条件表达式 then 执行语句 else 执行语句
条件表达式   → 算术表达式 关系运算符 算术表达式
关系运算符   → < | <= | > | >= | = | <>

算术表达式   → 项 { - 项 }
项           → 因子 { * 因子 }
因子         → 整数 | 标识符 [ ( 算术表达式 ) ]
```

说明：

- 原说明语句表、执行语句表、算术表达式和项中的左递归已去除。分程序中把说明语句后的分号提到一起：下一个单词是 `integer` 时继续读取说明，否则开始读取执行语句表。
- 变量说明与函数说明都以 `integer` 开头；提取该公共部分后，再根据后续单词判断。因子中的变量和函数调用也先读取标识符，再看后面是否有 `(`。
- 原文法使用了“函数调用”，但没有给出其产生式。为支持样例 `F(n-1)`，这里补充为“标识符后跟一对括号，括号内为一个算术表达式”。这是依据样例作出的约定。
- 严格按给出的表达式范围，只支持 `-`、`*`；括号用于函数调用，普通的 `(a-b)` 并未出现在给定的 MINI 文法中。每个函数恰有一个形参，调用恰有一个实参。
- 每个分程序至少有一个说明语句和一个执行语句；`if` 必须带 `else`。嵌套 `if` 时，按递归结构先完成内层语句，再匹配外层的 `else`。

## 变量表与过程表约定

实验说明要求 `.var` 每行依次输出 `vname vproc vkind vtype vlev vadr`，`.pro` 每行依次输出 `pname ptype plev fadr ladr`。说明未给出部分字段的完整取值，以下是本项目暂定的约定，不是老师给出的示例：

- 主程序在表中记作 `<main>`，层次为 0；函数层次比直接包含它的过程高 1。`<main>` 是表中的标记，不是源语言标识符；主程序没有返回类型，`ptype` 用 `-` 表示。函数类型与变量类型写作 `integer`。
- `vkind` 为 0 表示普通变量，为 1 表示形参。函数头里的形参先记作形参；函数体中第一次遇到同名声明时，将其关联到形参表项，不重复增加普通变量。
- 所有变量按所属过程分组写入 `.var`，过程按分析发现的顺序排列；同一过程内保留形参及声明的先后次序。`vadr` 从 0 开始，表示该变量在整个变量表中的位置。
- `fadr` 和 `ladr` 分别为该过程变量在变量表中的起止位置，均包含端点；没有变量时均记为 `-1`。分组后再确定地址，避免嵌套函数的变量把外层过程的区间截断。
- 实验说明将变量名和过程名定义为 `char(16)`。建立表时若名称超过 16 个字符，报告符号表错误，不悄悄截断；这不是词法错误或语法错误。
- 分析时用内部作用域区分过程；输出格式只包含过程名和层次，没有父过程字段，因此不同作用域中重名过程的表项可能无法仅凭文本完整区分。

按以上约定，老师样例一的表项预计如下，只用于说明字段和编号：

```text
sample1.var                 sample1.pro
k <main> 0 integer 0 0      <main> -       0 0 0
n F      1 integer 1 1      F      integer 1 1 1
```

其中 `m` 没有出现在声明中。是否声明不属于语法匹配；目前不检查未声明引用，也不凭使用位置为它虚构表项。除形参与其第一次同名声明的关联外，目前不检查重复声明；如果后续加入这些语义检查，应与语法错误明确区分。

## 测试与结果

使用 Python 3 标准库的测试脚本，从源程序开始运行两个分析器，并核对输出文件。测试在临时目录中进行，不覆盖工程已有的运行结果。在 `syntax/` 目录依次执行：

```sh
cmake -S ../lexical -B ../lexical/build
cmake --build ../lexical/build
cmake -S . -B build
cmake --build build
python3 tests/test_pipeline.py
```

阶段五的 12 组测试均通过：

| 测试内容 | 检查结果 |
| --- | --- |
| 老师的样例一 | 词法、语法无错误；变量表和过程表与约定一致 |
| 老师的样例二 | 无词法错误；报告 4 处语法错误并保留识别出的变量表项 |
| `tests/nested.mini` | 嵌套函数、形参、变量层次和地址区间正确 |
| `tests/errors.mini` | 报告 5 处错误，并继续分析后续语句 |
| 词法与语法边界 | 覆盖单词种别、运算符、嵌套条件、行尾、空文件和名称长度 |
| 文件和恢复 | 检查损坏的 `.dyd`、旧错误文件清空、输出冲突及符号链接保护 |

已有补充样例的运行结果保存在 `output/nested.*` 和 `output/errors.*`；它们的词法结果在 `../lexical/output/`。要重新生成，在 `lexical/` 目录运行：

```sh
./build/mini_lexer ../syntax/tests/nested.mini
./build/mini_lexer ../syntax/tests/errors.mini
```

然后回到 `syntax/` 目录运行：

```sh
./build/mini_parser ../lexical/output/nested.dyd
./build/mini_parser ../lexical/output/errors.dyd
```

`errors.mini` 是错误测试，语法分析器返回非零状态是预期结果。测试覆盖了指定案例，不能证明分析器在所有输入下都完全正确；错误恢复也可能产生连带提示。
